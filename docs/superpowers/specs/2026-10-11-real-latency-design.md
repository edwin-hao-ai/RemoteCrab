# 真实端到端延迟（D3）设计

> 读者：实现者。本文先说清"今天的数字是什么、为什么不能说它是延迟"，再给一个
> **可证伪**的测量法。**未批准前不动代码。**

---

## 1. 背景与根因

- 控制面板/托盘里的「延迟」来自 `IBLatencyTracker` —— 那是 **ping 的 RTT（网络往返）**，
  **不是**「手机拍到 → Mac 显示」的玻璃到玻璃延迟。
- PRD 写着「< 200ms」，但**没有任何东西测量过它**。
- 这正是本项目教训 141 的形状：**一个"被计算出来、从没被测过"的数字，会被当成事实。**
  在它被真正测出来之前，**任何"低延迟"的说法都是没有证据的**。

## 2. 硬骨头：跨设备时钟

手机的 `captureMicros` 和 Mac 的 `now` 在**两块不同的表**上。直接相减 = 把时钟偏差
当成延迟。所以要么**估偏差**，要么**用光学做真值**。

## 3. 三个层次（诚实分级，不混为一谈）

| 指标 | 准不准 | 包含什么 | 怎么得 |
|---|---|---|---|
| **A. 网络单程** | 估 | 只有链路 | `pingRTT / 2`（假设对称） |
| **B. 端侧管线** | **精确** | 到达→解码→上屏（**不含**手机采集与网络） | Mac 本地打点 |
| **C. 玻璃到玻璃** | 需光学真值 | 全部 | 见 §5 |

**建议**：UI 同时给 **B（精确、本地可测）** 和 **A（估算、明确标注"估算"）**，
**绝不把 A/ B 说成"端到端"**。C 只在验证时用，不进产品 UI。

## 4. 测 B（精确、可立即做、无跨设备问题）

在 Mac 接收端打三个点，全是**同一块表**：
1. `frameArrivalMicros`：`.video` 帧到达解析器时。
2. `decodedMicros`：`H264Decoder.onDecoded` 回调时。
3. 若走虚拟摄像头/预览：`displayedMicros`。

`B_decode = decodedMicros - frameArrivalMicros`；`B_display = displayedMicros - decodedMicros`。
用**本流自身的中位数**做基线，报"超过中位数 N 倍"的尖峰（场景无关，符合规则 3）。

## 5. 测 C（光学真值，仅用于验收）

1. Mac 全屏放一个**每帧变化的时间码/闪烁方块**（自己画，帧号编码进亮度）。
2. 手机摄像头对着它拍。
3. 手机采集到的帧里读出**方块当初的帧号**，与 Mac 当前显示的帧号比 → 真实玻璃到玻璃。
4. 用同一台 Mac，旁路手机直接看屏 → 得到"Mac 自显示"的基线，相减。

这一步**替换掉所有估算**，是唯一能证伪 §3 数字的方法。

## 6. 若要给"估算的端到端"（可选）

- 用 ping 估偏差 `offset ≈ macSendMicros - (phoneRecvMicros)`，取多次 RTT/2 的中位数。
- 手机在**每帧**（或每 N 帧）带 `captureMicros`。为省带宽：**每 N 帧一条极小的
  `latencyStat` 帧**（不塞进 H.264 NAL，保持视频路径不变）。
- `e2e ≈ (macNow - offset) - phoneCaptureMicros`。
- **必须自证**：`offset` 应稳定；漂移 = 数字作废。UI 只显示它并标注"估算"。

## 7. 影响面

- 精确的 B：只在 `ReceiverSession` + `StreamTelemetry` 里加时间戳与中位数统计（**无 wire 改动**）。
- 可选的估算：wire 加一个小 `latencyStat` 帧（`#[serde(default)]` 兼容）+ 手机采集时间戳。
- UI：控制面板/托盘显示 B（+ 可选 A），**文案区分"端侧"与"估算"**。

## 8. 验证

- **B**：单元测（打点差值）；真机看解码/显示耗时是否合理（个位数 ms 级）。
- **C**：光学法给真值；**用它证伪**估算的数字（这是唯一权威）。

## 9. 未决问题

1. 先只做 **B（精确、便宜）**，还是连"估算的端到端"一起做？
2. 光学法（C）要不要沉淀成一个 `scripts/` 工具，供以后回归？

## 10. 诚实边界

- B 与 C 我都能在本端实现/测量；**C 需要真机 + 一次人工对时**。
- 估算法（§6）如果做，必须**同时给出它的证伪路径**，否则就是又一个"从没被测过的数字"。
