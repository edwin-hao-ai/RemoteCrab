# RemoteCrab 连接可靠性：三个根因与修复（2026-09-23）

# 结论
用户反复「iOS 连不上 Mac」有三个独立根因，都已在 2026-09-23 修复并真机验证：

1. **Mac 缺握手超时（头号根因）**。TCP 到 `.ready`、发了 `clientHello` 但收不到
   `sessionReply`（手机在握手途中被后台挂起）时，Mac 卡在 `.handshaking` 且
   `connection != nil`，而 `handleDiscovered` 只在 `connection == nil` 或
   `.connecting` 时拨号 → 永远不再重拨。直连有 8s 超时，Bonjour 没有。
   修复：6s 无 `sessionReply` 就放弃并重连（`pending` 等批准不误杀）。提交 `0ec60d6`。

2. **Mac 只对有 token 的手机自动拨号**。重装/迁移/换 mac.id 后 token 丢失 → Mac 静默不拨。
   修复：改为「发现即拨」（优先 token 命中，否则拨第一个发现的），由 iPhone 侧裁决
   accepted/pending/busy。提交 `f6a38af`。

3. **App 被 iOS 后台挂起**，监听关闭，Mac 再也发现不到。
   修复：`UIBackgroundModes: [audio]` + 静音保活会话（见另一条记忆的 mic 分类坑）。

配套：iPhone 侧 owner 静默 10s 释放（半开 socket 不再永久 busy）；Mac 侧 8s 无 pong 判死链。

# 验证方法（复用）
- 半开模拟：`kill -STOP <receiver pid>` 15s 再 `kill -CONT` → 观察 iPhone 主动 reset + Mac 重连。
- `log stream --predicate 'subsystem == "com.remotecrab"' --info`
- 手机日志：`xcrun devicectl device copy from --device <UDID> --domain-type appDataContainer
  --domain-identifier com.ibridge.iBridgeCapture --source Documents/forensic.log --destination /tmp/f.log`
  （macOS 没有 GNU `timeout`；`idevicesyslog` 需要 `-u`。）

# 坑
- zsh 有内置 `log`（对数函数），会吃掉 `/usr/bin/log`；脚本里用 bash 没问题。
- `defaults` CLI 对沙盒过的 bundle id 仍解析到旧容器；直接改 `~/Library/Preferences/<bid>.plist` + `killall cfprefsd`。
