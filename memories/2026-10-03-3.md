# 经验：修测试同样受规则 3 约束；断言必须双向验证；注释是规范代码是历史

# 三条可复用的经验（2026-10-03 Windows 对齐这一轮）

## 1. 我在**测试**里犯了规则 3 的错——而且犯了两次

AGENTS.md 规则 3 是「先找根因再改代码」。这一轮我修 e2e 断言时，
从日志的 `origin/size` 几何**推断**「光标是否已在目标窗口内」，两次都错：

- 第一次用 `sed 's/…\([0-9-]*,\?[0-9]*\)…/'`——**BSD sed 没有 `\?`**，
  正则静默匹配不到任何东西，于是「没有回归」看起来像是通过。
- 第二次逻辑上就错：「和点击同一目标」**不等于**「光标已在目标内」，
  因为前一次滚动可能把光标留在**另一块显示器**上。

最终解法：让 `CGEventInjector` 在自己的 marker 行里说出原因，断言只读。

**教训**：当一个断言必须区分两种都合法的结果时，原因必须来自**持有该状态的
那个组件**。下游重新推导 = 重新引入 bug。而且这个错误我只在**测试**代码里犯，
说明规则 3 同样适用于「修测试」——测试代码也是代码。

## 2. 断言必须**双向**验证，否则你交付的可能抓不住任何东西的假绿

修好之后我拿一份手工构造的「注入一次偷走」日志确认它**仍然会 FAIL**。
如果只验真实 run 通过，我会交付一个「看起来修好了、其实抓不住回归」的断言。

配套：`scripts/e2e-cursor-guard.sh` 单独成文件就是为了能对着**已知**日志跑两个
方向——一个只有实跑 30 秒竞态才能执行的断言，没人能证明它还抓得住东西。

**还要注意「要求正面证据」可能是不可满足的**：我最初要求「必须看到一次滚动
没动光标」，但滚动脚本和目标切换脚本在同一条时间线上赛跑，那种情况**可能根本
不发生**——于是它在一次正确的 run 上失败了。防空过要靠要求**前置条件**
（有 click、≥1 次 post-click 滚动），而不是要求**结果**。

## 3. 注释是规范，代码是历史——分叉时先怀疑代码

`scrolling never steals the cursor` 上面那段注释**已经把意图写对了**：

> "the assertion is 'exactly one scroll was left alone' — the post-click
> scroll in the window the click landed in — rather than a global count"

而代码做的是**全局计数**——正是注释说它不做的事。这类分叉很容易被当成
「代码 bug 改代码」，其实**注释才是对的**，改代码才对。

另外一个小坑：`bash printf` **不展开 `\uXXXX`**，所以 `\u2713` 会被原样打印。
真机日志里那行显示 `\u2713` 而其他行都是正常的 ✓——用字面字形。

## 4. 交接文档也需要核对（本轮又验证了一次）

`docs/WINDOWS-GAPS-2026-10-03.md` 的 6 条论断**全部属实、行号也准**，但它
**漏了更严重的一半**（系统区无条件渲染，4 个坏按钮今天就在线上）。而且它的
「⊞ 不需要动协议」对**单独点 ⊞**成立、对**组合键不成立**。

→ 交接文档比记忆可靠，但**仍然要核对**，而且要核对「症状描述」而不只是
「给出的行号」。
