# RemoteCrab 1.0 App Store 拒审修复与重发（2026-09-24）

# 结论

## 三条拒审原因与修复
1. **2.1(a) 崩溃（点语音权限的 Allow 时）**。崩溃日志：
   `_dispatch_assert_queue_fail → swift_task_checkIsolated → TCC __TCCAccessRequest_block_invoke`。
   TCC 在**私有 XPC 队列**回调，而 `PermissionFlow` 是 SwiftUI View（隐式 @MainActor）→
   从后台 resume 被隔离的 continuation 会 SIGTRAP。修复：所有权限探针改 `nonisolated static`
   （相机/麦克风恰好在主队列，只有语音会崩——与 lesson 2 同类）。
2. **5.1.1 权限 UX**：前置卡按钮 Allow→Continue；**删掉 Not now**（必须始终进入系统请求）。
3. **5.2.5 "Mac" 商标**（名称/副标题）。关键：要扫**所有用户可见文案**——
   catalog 的**值**（不只 key）、`project-ios.yml` 的 **Info.plist 权限描述**（系统弹窗里显示，最易漏）、
   `ios-metadata.json`、**官网文案**、以及**截图合成脚本自带的标题**（`compose-asc-screenshots.py`
   把标题**烤进 PNG**，审核能看到）。统一用 computer/电脑。

## 发版踩的坑
- `ExportOptions.plist` 必须是 `method: app-store-connect`；残留的 `debugging` 会导出发签名 IPA，
  ASC 拒 `90161 Invalid Provisioning Profile`。
- **ASC 截图上传间歇性 `SSL: UNEXPECTED_EOF_WHILE_READING`**：API 与预签名上传主机在突发调用下会
  丢 TLS。curl/单发 Python 正常。修复：**每次新建 `ssl.create_default_context()` + 重试退避**，
  且 `request()` 与**裸的分片 `urlopen`** 两处都要（后者最易漏）。
- 版本可沿用（1.0），只升 build 号（→ 2026092401）。
- 官网部署核验：**比对线上与本地 dist 的哈希**。

## 复现/验证命令
- e2e：`./scripts/e2e-device.sh`（10/10）
- 修饰键：`REMOTECRAB_E2E_MODIFIER=58` → Mac 日志 `modifier key event`/`modified text a -> keycodes`
- 语音：`REMOTECRAB_E2E_VOICE=1` → Mac 日志 `typed text` 且**无** `backspace`
- 元数据/截图：`python3 scripts/ios-app-store-metadata.py --version 1.0 --metadata|--screenshots`

## 未验证（需真机手指）
- **Labs 两步激活**：设置里开实验室 → 回触控板点底部实验按钮才 ARMED。
  空中鼠标（CMMotionManager）、画圈滚动（角度识别）**从未真机测试**，e2e 不覆盖。
- 震动反馈：`UIFeedbackGenerator` 仅在「系统触感反馈」开启时播放；已加 `.record` 会话下的
  `setAllowHapticsAndSystemSoundsDuringRecording(true)`、去掉 `.duckOthers`、并在「强」档加
  `kSystemSoundID_Vibrate` 保底。
