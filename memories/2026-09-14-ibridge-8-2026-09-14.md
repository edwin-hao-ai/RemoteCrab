# iBridge 虚拟麦克风驱动:8 个坑全部修复并真机验证通过 (2026-09-14)

# iBridge 虚拟麦克风 (HAL AudioServerPlugIn) 完整踩坑记录

## 结果
Familiar Microphone 已是 macOS 系统级输入设备,真机全链路验证通过:
iPhone 麦克风 → WiFi → Mac App (MicRingWriter) → UDP 127.0.0.1:49182 →
HAL 驱动 → CoreAudio 设备 → 任意 App 可用。共 15+ commits,门禁全绿。

## 8 个坑(每个都曾让设备静默不出现)
1. 签名:必须 Developer ID Application,coreaudiod 拒收 Apple Development 签名
2. Info.plist 必须带 CFBundleExecutable,否则整个 bundle 被静默跳过
3. COM 布局:driver 结构体首字段必须是 AudioServerPlugInDriverInterface*(指针),
   AudioServerPlugInDriverRef 是指针的指针,按值放接口结构体 = NULL vtable 崩溃
4. QueryInterface 必须返回 ref 本身(*outInterface = inDriver),
   返回 &driver->mInterface 会让宿主把 reserved NULL 槽当 vtable
5. QI 必须 AddRef(COM 契约):宿主 get_asp_interface 在 QI 后立即 Release 工厂引用,
   不加引用计数 = 驱动首次使用前被释放 → SIGSEGV at 0x10
6. 架构必须 x86_64:arm64 宿主是 arm64e,用 blraaz 指针认证调 vtable,普通 arm64 必崩
7. 必须实现 kAudioPlugInPropertyDeviceList ('dev#'):宿主 Initialize 后先问设备列表,
   返回未知属性就直接放弃,CreateDevice 永远不会被调用
8. 必须实现 kAudioObjectPropertyClass ('clas') + ZeroTimeStampPeriod ('ring');
   且 HasProperty 声称的属性 GetPropertyData 必须能给(否则枚举中途出错,发布中止)

## 方法论(比坑本身更值钱)
- dlopen 测试台 scripts/mic-driver-harness.c:复演宿主真实调用序列
  (factory → QI → Release → Initialize → dev# → clas → ring → uidd → 属性树),
  改驱动先过它再装真机
- 反汇编宿主二进制(otool -tvV Core-Audio-Driver-Service.xpc)看真实调用序列,
  是"测试台全过但真机还崩"时的终极手段
- 驱动里全链路 os_log(subsystem com.ibridge.micdriver),静默问题必须先可观测
- autoloader 模式:Terminal 常驻脚本(用户输一次 sudo)监听 trigger 文件,
  自动 ditto 驱动 + killall coreaudiod + 执行排队的 root 命令(sample 等),
  迭代不再要用户点安装器
- 验证发布用 C 工具查 kAudioHardwarePropertyDevices + 逐设备 UID;
  system_profiler 有缓存不可用

## 苹果自身的坑(会误伤排查)
coreaudiod 100% CPU + 所有音频客户端首次查询卡死 = AirPlayXPCHelper
重注册风暴(1.7 万次,sample 显示 HALC_ShellSimpleProxyList::Reconcile 递归),
与第三方驱动无关,热点网络加重。缓解:sudo killall AirPlayXPCHelper。
