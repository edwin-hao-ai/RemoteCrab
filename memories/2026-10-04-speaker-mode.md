# 扬声器模式：已证明的和没证明的

## 结论先说

**功能还不能用。** 界面正常、协议正常、数据在流动，但**听到的是静音**。

## 真机实测到的（iPhone 14 / iOS 26，Mac 真机）

| 环节 | 证据 |
|---|---|
| iOS 音频会话 | **5 步 0 失败**：`.record` ↔ `.playback` 双向交接都成功，且**不需要任何新权限** |
| Mac 采集 | **真的抓到了声音**：643 个包里 103 个非零，peak 8855 = 测试音符的振幅 |
| 传输 | 707 个包到达手机，705 个播出，0 饿死 |
| 手机的能量测量 | **`pcmRms=0` 且包络为空 —— 与 `enqueued` 在涨自相矛盾** |

所以剩下的缺口在「Mac 组装出非零的包」到「手机测到非零」之间，**且手机侧的测量代码本身也可疑**
（包络在增长却打印空字符串，这是不自洽的）。

## 两个我判错的地方

1. **「整条链路都是静音」是错的。** 测试信号是 8 个音符带 250ms 间隔，所以**约一半的包本来
   就该是零**，我把音符间的静音读成了故障。真值是 103/643 非零。
   —— 只有**有结构的**测试信号才能区分「完整到达」和「片段到达」。

2. **两个电平日志都是累计平均值，我却拿它们比同一瞬间。** `capturedRms` 是全程累计，
   `ringNewest` 是最近一个 512 帧块（正好落在间隔里就是 0）。

## 我删掉了顶栏两个菜单（已恢复）

用 Python 文本切片替换 UI 代码时，`old_end` 的锚点 `.frame(width: 44, height: 44)`
**在顶栏里每个按钮后面都有**，于是「替换区间」跨过了镜像菜单和整个 overflow 菜单，
把它们一起替换掉了。**它编译通过、所有测试通过**，只有用户看手机才发现。

已按原样恢复并逐项核对（11 个标记 orig == now），并加了 `TopBarIntegrityTests`
在源码级断言这些控件仍然存在。

**教训：这个 session 我被自己的 harness 骗了 6 次**（过期二进制、DerivedData 挑错、
`pipefail`+`grep -q`、没检查 Mac 端、日志窗口开在启动之后、还有这次删 UI），
**每一次都是「编译通过 + 测试全绿」但结论是错的**。
