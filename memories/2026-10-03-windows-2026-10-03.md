## 交接文档说的 vs 实际的

`docs/WINDOWS-GAPS-2026-10-03.md`（02:34 那次提交）说「情景模式在 Windows 上

## 做了什么（11 个提交）

1. **`meta = 16` 修饰键位**（Swift + Rust 两端）—— 之前只有 1/2/4/8，
   而 `COMMAND` 在 Windows 上塌缩成 Ctrl，所以 ⊞E/⊞R/⊞D/⊞L **一个都发不出去**。
   交接文档说「协议不用动」，那只对单独点 ⊞ 成立。
2. **修 4 个坏按钮**：亮度**移除**（不做死按钮）、锁屏 ⌃⌘Q → **⊞L**（原版塌缩成
   `Ctrl+Q`，会**退出**用户正在用的软件）、Safari → 「浏览器」（原来打开 Bing）。
3. **⊞ 键行顶替 ⌘**，不是并存 —— `windowsLabel` 把 ⌃ 和 ⌘ 都渲染成 `"Ctrl"`，
   Windows 用户本来就在看两个同名按钮。
4. **每平台独立动作集**，Windows 端**绝不回退**到 Mac 动作
   （`windowsActions ?? []`，不是 `?? actions` —— 回退产生的是*错*按钮）。
5. **套件格式留缝**：`schemaVersion` + `source` + 优先级 `userFile > remote >
   builtin`（同 id 覆盖），`Documents/RemoteCrab/Profiles/*.json`，**零网络**。

Mac 侧**零影响**：原有 25 个 `ContextProfilesTests` 一字未改，全绿。

## 主动砍掉的（等真机确认再加）

| 项 | 原因 |
|---|---|
| `AppInfo.appRef`（交接清单第 2 项） | `windowsProcessNames` 按进程名解决同一问题，不改协议、不用双端重建。等出现第二个非 Windows 平台再拆 |
| agent 套件的复制/粘贴 | Windows Terminal 组合键无法从文档确认。「复制」变成中断正是这次要消灭的失败 |
| PowerPoint（`POWERPNT`） | F5/Shift+F5 需要 `keymap.rs` 支持扩展功能键（F1–F12），未验证。`testPowerPointIsNotYetMapped` 断言它**没有**映射，让省略读起来像决定 |
| 其余 13 个套件 | 没有可靠按键依据。匹配不上落到系统控制区——**那是诚实且能用的行为** |

## 只上「有据可依」的三个套件

- `agent` → WindowsTerminal / powershell / pwsh / cmd / conhost（Claude Code、
  Codex CLI、OpenCode、Gemini CLI、Aider、goose 都在里面；终端无法区分是哪个
  agent，与 Mac 同理）
- `editor` → Code / devenv / cursor / notepad++（VS Code 官方键位表）
- `browser` → chrome / msedge / firefox / brave（Chromium/Firefox 通用 Ctrl）
